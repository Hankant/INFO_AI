# PPT 叙事顺序与文献使用总则

## 一、为什么要单独写这份总则

当前三篇文章的 PPT 容易出现一个共同问题：

- 研究者自己已经非常熟悉实验设计，于是会过早进入方法、条件、变量和技术细节；
- 但导师或听众还没有先被说服：这个问题为什么重要、现有研究为什么不够、为什么这个 gap 值得单独做一篇。

结果就是：

- 设计听起来很复杂；
- 但问题意识不够清楚；
- 文献库很多，却没有真正转化成“为什么值得研究”的论证。

因此，从现在开始，**每个子课题的 PPT 都应优先遵循同一套叙事顺序**，先建立问题意识，再进入设计。

## 二、每个子课题的推荐展开顺序

无论是总领之后的 Paper 1、Paper 2，还是未来的 Paper 3，都优先按下面顺序展开：

1. 先用几个生活化、具体、直观的例子把问题带出来。
2. 再介绍现有研究已经做了什么，传统理论通常怎么理解这个问题。
3. 再指出 gap：哪里没解释清楚，哪里被混在一起了，为什么这个问题必须单独研究。
4. 在 gap 成立之后，顺势提出研究问题 `RQ`。
5. 再介绍我们的 framing / analytical framing：我们到底把这个问题理解成什么。
6. 再说明所依托的理论基础或机制逻辑。
7. 再讲实验原型：我们为什么选这个任务原型，它要满足什么识别要求。
8. 然后才进入具体实验设计。
9. 最后讲预期结果、预期识别到什么、这篇文章能贡献什么。

一句话版本：

`例子 -> 现有研究 -> 传统理论 -> gap -> RQ -> framing -> 理论基础 -> 实验原型与要求 -> 实验设计 -> 预期结果`

## 三、这个顺序为什么比“直接讲设计”更好

因为导师最先要决定的不是：

- 你这个模型写得细不细；
- 你这个条件有几个；
- 你这个变量定义得精不精。

导师最先决定的是：

- 这个问题是不是值得单独研究；
- 现有研究是不是真的没解决；
- 你的 framing 有没有比现有说法更清楚。

所以 PPT 里最先要完成的任务不是“展示你设计得很复杂”，而是：

> 让老师承认：对，这里确实有一个 gap，而且不研究它不行。

## 四、生活化例子的作用

每个子课题开头都应有 1–2 个具体、生活化、非技术性的例子。

这些例子的功能不是“活跃气氛”，而是帮老师先建立直觉：

- Paper 1：AI 给了一个看似完整的答案，人为什么会更少去找额外证据？
- Paper 2：AI 前面犯几次错，为什么后面即使恢复了，人还是不太愿意继续用？
- Paper 3：AI 参与决策以后，责任到底还算不算人的，还是结构本身变了？

例子的要求：

- 要短；
- 要具体；
- 要和研究问题直接同构；
- 不要举太花哨、太行业化、太强情绪色彩的例子。

## 五、现有研究与传统理论该怎么讲

这一部分不是文献目录，也不是“我读过很多篇论文”的展示。

真正要完成的是两件事：

1. 告诉老师，现有研究的主流做法是什么。
2. 告诉老师，传统理论通常怎么理解这个问题。

因此更好的讲法是：

- 先压缩成 2–3 个主流处理路径；
- 再讲它们共同遗漏了什么。

不要做成：

- 一页塞十几个作者名字；
- 每篇文献都提一句；
- 结果没有形成“主流解释结构”。

## 六、gap 要怎么成立

gap 不是一句“过去研究较少关注”。

gap 必须明确回答：

1. 现有研究主要解释了什么。
2. 它没有解释什么。
3. 这个“没解释的部分”为什么不是边角料，而是核心问题。

因此每篇的 gap 最好都至少带有下面三个元素：

- `what has been done`
- `what remains unresolved`
- `why the unresolved part matters`

## 七、RQ 应该出现在什么位置

RQ 不要一开始就冒出来。

更好的位置是：

- 先用例子和现有研究把问题逼出来；
- 再由 gap 推到 RQ。

也就是说，RQ 应该让老师感觉是“顺理成章被问出来”的，而不是“作者自己想问就问”。

## 八、framing 和理论基础的关系

很多 PPT 容易把 `framing`、`theory`、`mechanism` 混成一团。

更稳的分法是：

- `framing`：我们把问题看成什么。
- `theory / mechanism`：为什么会这样。

例如：

- Paper 2 的 framing 不是 generic trust，而是 repeated feedback 下的 dynamic reliance updating。
- 然后理论上再去讲：为什么 error shock 会改写后续 reliance path。

## 九、实验原型和实验设计要分开讲

这是当前 PPT 很容易出问题的地方。

### 先讲实验原型

先回答：

- 为什么选这种任务原型？
- 它要满足什么要求？
- 它帮助我们隔离了什么？

### 再讲实验设计

再回答：

- 具体条件怎么分；
- 操控是什么；
- 比较是什么；
- 识别怎么建立。

如果不先讲实验原型，老师会觉得：

- 为什么非得做这个任务？
- 为什么非得这么复杂？

## 十、技术细节应该怎么处理

当前答辩 PPT 不需要把技术细节讲得太满。

原则是：

- 只保留那些能防止误解、对识别关键的细节；
- 不要把推导、参数、技术结构当成主叙事。

尤其不要让老师在还没理解问题时，就先被以下内容拖住：

- 模型细节；
- 长公式；
- 太多 block / condition 名词；
- 过细的实现设定。

技术细节最好的位置通常是：

- 方法页里的一个“足够解释误解”的版本；
- 或者答辩追问备用页；
- 而不是前 3–4 页的主叙事。

## 十一、文献库到底应该怎么用，才不算浪费

你现在的文献库不应该主要用来“证明你看过很多东西”，而应该用来服务三件事：

1. 帮你把现有研究压缩成清楚的几条主流路径。
2. 帮你把传统理论说准确，而不是凭直觉讲。
3. 帮你把 gap 讲成真的存在、而且值得研究。

所以文献库最有价值的用法，不是在后面加一堆 citation，而是在前面几页帮你做出这三个判断：

- 现有文献到底已经讲到哪一步了；
- 传统解释为什么不够；
- 你的问题为什么不是重复造轮子。

## 十二、对 PPT agent 的硬要求

从现在开始，后续所有子课题 deck 都应优先遵守以下要求：

1. 不要一开始就进入实验设计。
2. 先用生活化例子把问题带出来。
3. 必须有一页明确讲 `existing work / traditional view / gap`。
4. RQ 必须在 gap 之后出现。
5. `framing` 和 `design` 要分开讲。
6. 先讲实验原型为什么合理，再讲实验设计怎么展开。
7. 技术细节要节制，重点是防止误解，不是堆复杂度。
8. 文献库优先用于支撑前面的 problem framing，而不是只在结尾挂引用。

## 十三、最简版模板

如果某个子课题页数不多，最简版也应尽量保留这个结构：

1. 生活化引入
2. 现有研究与传统理论
3. gap 与 RQ
4. framing 与理论基础
5. 实验原型与设计
6. 预期结果与贡献

如果页数再压缩，也优先保留：

`例子 -> 现有研究/gap -> RQ -> framing -> design -> expected results`
