# 企业任务级生成式 AI 推理预算配置：技术路由已经出现，组织净价值仍缺因果证据

## 摘要

企业面临的不是一个单纯的“是否采用 AI”问题，而是一个任务级顺序决策：是否调用 AI、调用哪一档模型、投入多少推理预算，以及何时停止或升级。现有研究已形成三块互补但未闭合的证据：`value of computation` 提供“额外计算是否值得”的规范性准则；任务分配与比较优势研究解释不同任务、员工和 AI 组合的收益异质性；`LLM routing`、`cascade` 与 `test-time compute allocation` 则在质量阈值外生给定后优化模型和 token 成本。[1–14] 组织实证同时表明，AI 的时间与质量效果随任务和员工显著变化，但主流研究大多比较“有无 AI”，没有随机改变模型价格档、记录实际 token 费用并将人工核验和错误损失纳入同一个结果变量。[15–18] 本文归纳认为，最有价值的研究缺口不是再提出一个笼统的 “AI ROI” 指标，而是对 `worker–task–model` 组合的边际净价值进行因果估计，并据此比较统一用便宜模型、统一用昂贵模型、静态路由和条件升级四类政策。

## 1. 研究问题

本文固定以下三个问题：

- **RQ1：** 哪一套既有理论能够同时解释“不用 AI—使用低成本模型—使用高成本模型—条件升级”的选择？
- **RQ2：** 现有技术和组织实证分别能够测量哪些成本与收益，又遗漏了什么？
- **RQ3：** 在已有 `token leverage`、企业 AI tokenomics、token 预算激励和管理者 AI 配置研究之后，什么增量仍具有清楚的理论与经验边界？[4–8]

研究主体是企业或获得任务配置权的管理者；分析单位是一次具体的 **task execution episode**，不是整个职业、员工或企业。模型价格只是成本属性，不是能力的替代指标；模型能力必须由该模型在相应任务上的实际质量、错误分布和下游后果来测量。[2–8]

## 2. 检索与证据边界

本轮检索覆盖四条路径：规范性决策理论、任务生产与组织配置、生成式 AI 工作场所实证、成本感知的 LLM 路由与推理预算。时间范围以 2023–2026 年为主，并回溯 `value of information`、`value of computation` 和 `algorithm selection` 的奠基文献。只有能够从期刊、正式会议、NBER、作者原文或可核验工作论文页确认标题、作者与主张的文献进入正文；最终保留 21 项核心来源。

| 证据类型 | 能回答的问题 | 本轮使用边界 |
|---|---|---|
| 规范性理论 | 什么条件下额外信息或计算值得购买 | 提供决策准则，不直接提供企业参数 |
| 分析模型与校准 | 固定成本、边际推理成本、任务规模和组织能力如何影响采用 | 多数不是企业微观因果识别 |
| 随机实验与现场数据 | AI 对时间、质量、产出和员工异质性的影响 | 多数不改变模型档位，也不记录完整推理成本 |
| CS benchmark 与系统实验 | 如何在给定质量目标或预算下选择模型、token 或升级路径 | benchmark 分数不等于业务价值 |

## 3. 理论概念审计

### 3.1 主理论：Value of computation / metareasoning

Russell 与 Wefald 的原始术语是 **value of computation** 与 **metareasoning**：计算行动的价值来自它改善外部行动选择的预期能力，并须扣除计算本身的成本；它不等于“更多计算通常更准”。[1] 该概念属于任务内部的顺序决策层，位于 AI 调用、再次采样、模型升级和停止规则的位置；经验上对应升级前后的最终任务质量、错误损失、token 费用、延迟及人工复核时间。[1]

它能区分两种竞争性政策：统一给所有任务使用最强模型，或者只有当额外计算会显著改变最终产出或减少预期损失、且收益超过完整增量成本时才升级。[1] 对直接生成文案或代码的任务，应比较最终产出的期望业务效用；不能把所有生成任务都强行解释为 `value of information`。[1]

### 3.2 异质性基础：Task-based production / assignment 与 human–AI complementarity

任务分配研究把任务视为生产商品或服务的一项工作活动，并按照人、技术和资本在具体任务上的比较优势配置投入；任务不等于职业，`routine/nonroutine` 也不是生成式 AI 的普遍能力边界。[2,3,7] Fügener、Walzner 与 Gupta 进一步区分 **between-task complementarity** 和 **within-task complementarity**：前者来自人和 AI 在不同任务上的相对优势，支持跨任务重分配；后者来自人机在同一任务内正确结合信息的能力，支持增强式协作。[2]

这组理论位于模型的异质性来源位置，经验上要求同一任务在人类、不同模型和不同人机组合下的质量、时间、复核与返工数据。[2,3] 它解释为什么必须研究 `task–worker–model` 组合，但不能单独推出应该投入多少 token 或何时升级。[2,3]

### 3.3 执行框架：Algorithm selection、LLM routing 与资源配置

Rice 的 **algorithm selection problem** 是根据问题实例的可测特征，从候选算法中选择在指定绩效准则上表现最好的算法；它不假定存在一个全局最优模型。[9–14] 在 LLM 语境中，`query routing` 指生成前选模型，`cascade/deferral` 指先调用低成本模型再决定是否升级，`test-time compute allocation` 指模型确定后分配采样次数、搜索深度或推理 token；这些术语不能互换。[9–14]

这些方法位于执行层：在企业先定义质量阈值、错误损失和预算后，利用历史任务数据实施路由。传统 benchmark 的准确率、LLM judge 或偏好分数不自动包含员工时间、合规风险、客户流失和人工核验成本，因此 `LLM routing` 不是完整的企业理论。[9–14]

### 3.4 不宜作为主理论的概念

- **Rational inattention** 研究决策者在信息处理有成本或容量限制时如何内生选择信息结构；若只有 token 支出，没有注意策略、信息选择或容量数据，就不能真正检验该理论，因此不适合承担单次模型选择的主干。[1]
- **Technology Acceptance Model** 和 **Task–Technology Fit** 主要解释接受、使用或技术—任务匹配，不能直接给出模型价格、错误损失或升级停止规则。
- **Transaction cost economics** 适合研究自建模型还是采购 API 等治理选择；对一次具体任务是否多花推理成本调用更强模型，没有直接的边际质量规则。

## 4. 三条文献线并未闭合

### 4.1 企业理论已经触及 token，但缺少直接因果验证

| 研究 | 原始对象与分析层级 | 已解决的问题 | 未解决的问题 |
|---|---|---|---|
| Seagraves 与 Sirmans，`Token Leverage` [4] | `worker–task`；实际推理支出除以任务劳动成本 | 说明二元“采用/未采用”会混合合理使用、合理不用、被迫过度使用和受限不足使用 | 理论论文；没有随机化模型档位或企业微观因果验证 |
| Makridis，`AI Tokenomics and the Firm` [5] | 企业任务与流程；`process capital` | 说明相同 token 价格下，流程重构、上下文、路由和验证能力会造成不同回报 | 主要是理论与校准模拟；没有识别任务级边际回报 |
| Yu，`Token Budgets as Incentive Instruments` [6] | 企业—员工；token 预算 | 把预算视为激励工具，比较 productive experimentation 与 private gaming；预算既降低员工试验成本，也可能补贴非生产性使用 | 委托—代理模型尚无实验验证；回答“给员工多少预算”，不回答“某个任务应选哪档模型” |
| Lindenlaub 等，`Beyond Exposure` [7] | 任务、工人、职业 | 用比较优势和推断的 AI user costs 解释实际采用，优于只看技术暴露 | user costs 来自揭示偏好推断，不是实际 token 价格与人工复核成本 |
| Hauser、Li 与 Xu，`Misperceiving the Frontier` [8] | 关联的工人—管理者实验 | 检验管理者能否预测不同任务和工人上的 AI 收益及配置意愿 | 未把多模型价格档、token 预算、条件升级和下游错误损失作为核心处理 |
| Lashkari 等，`AI and Scale` [3] | 任务—企业—宏观 | 把固定训练/微调成本与边际推理成本纳入任务自动化和规模比较优势 | 主要校准计算机视觉自动化，不是生成式 AI 员工任务的现场配置 |

因此，不能声称“企业任务级 AI 成本尚无人研究”。更准确的空白是：**尚缺对不同模型档和推理预算在真实 `worker–task` 上的边际净价值进行随机化估计，并把该估计转化为经留出样本验证的配置政策。**这一判断属于本文归纳，且应随 2026 年工作论文快速更新。

### 4.2 技术路由解决的是下游问题

FrugalGPT、Hybrid LLM、RouteLLM 和 BEST-Route 均表明，在各自 benchmark 与价格设定下，按 query 选择模型、级联调用或联合选择模型与采样次数能够改善质量—成本前沿。[9,11–13] 其中 Šakota、Peyrard 与 West 的批量任务分配比纯逐请求路由更接近企业预算配置，但其目标仍是外生给定的任务表现和 API 成本。[10]

这些结果不能直接推出“简单任务用便宜模型、复杂任务用昂贵模型”。RouteLLM 的域外表现依赖训练分布，而 2026 年 LLMRouterBench 的统一评估发现，多种近期路由器表现接近，部分方法不能稳定超过 `best single model`，与 oracle 仍存在明显差距。[12,14] 更强的反例是，近期 agentic coding 研究发现相同任务的 token 消耗可高度波动，更多 token 与更高正确率并非单调对应，模型也不能准确预报自身成本。[19]

### 4.3 工作场所实证证明异质性，却通常不测推理价格

Noy 与 Zhang 在中等难度专业写作任务中发现生成式 AI 改善完成时间与质量；Brynjolfsson、Li 与 Raymond 在单一客服环境中发现平均生产率提高约 15%，且收益主要集中于较低技能和经验较少的员工。[15,16] Dell’Acqua 等则显示任务边界是参差的：在 AI 能力边界内使用 AI 可提高速度与质量，而在边界外的复杂任务中，使用 AI 的参与者更不容易得到正确答案。[17]

Dillon 等覆盖 66 家企业和 7,137 名知识工作者的随机现场实验发现，实际使用者每周减少约两小时电子邮件时间，但未检测到任务数量或构成的明显变化。[18] 这些研究共同反对用一个平均生产率系数配置所有任务；但它们主要研究固定工具的访问或部署，没有随机改变模型价格档，也没有把实际 token 支出、员工复核、返工和错误损失共同定义为主要结果。[15–18]

人工互补成本并非可以忽略。METR 在 16 名熟悉大型开源代码库的资深开发者中按真实 issue 随机允许或禁止 AI，观察到 AI 条件平均完成时间增加 19%；屏幕记录显示参与者把时间用于提示、等待和逐行复核，但研究没有记录实际 token 账单，也不能泛化为所有软件任务。[20] 另一项覆盖超过 100,000 名 GitHub 开发者的研究发现，AI coding agent 对 commits 的增幅在项目和正式发布层级明显衰减，说明任务级产出会受到后续人工瓶颈约束。[21]

## 5. 跨分支综合：真正的理论与经验断层

技术文献通常求解：

\[
\max_{m,b} Q_t(m,b)-\lambda C_{AI}(m,b),
\]

其中任务质量权重、预算或阈值已经外生给定。[9–14]

企业需要先求解的是本文归纳的任务级净值问题：

\[
a_{ijt}^{*}=\arg\max_{a\in\{H,L,P,L\rightarrow P\}}
E\left[V_t(Q_{ijt}(a))
-C^{AI}_{ijt}(a)
-w_j\{T^{use}+T^{review}+T^{rework}\}_{ijt}(a)
-L_t(error\mid a)\right].
\]

其中，`H` 是 human-only，`L` 是低成本模型，`P` 是高成本模型，`L→P` 是条件升级。`V_t(Q)` 是达到任务质量后的业务价值，`C^{AI}` 是实际推理费用，人工时间按相应劳动成本计价，`L_t` 是错误的下游预期损失。该式是实证决策规则，不应包装成一个新理论概念；其规范性依据来自 `value of computation`，异质性依据来自任务分配与人机互补研究。[1–3]

这个断层包含四个不能互相替代的量：

1. **任务成功的价值**，而不只是 benchmark accuracy；
2. **完整 AI 成本**，包括输入、输出、推理、重试和升级；
3. **人工互补成本**，包括提示、等待、复核、修改和错误恢复；
4. **错误后果**，同样的准确率在内部邮件、生产代码和客户决策上具有不同经济含义。

## 6. 建议研究方向

### 6.1 建议题目与主问题

建议中文题目：

> **企业应在何时升级 AI 计算？知识工作任务中的模型档位、人工核验与边际净价值**

建议英文题目：

> **When Should Firms Escalate AI Compute? Model Tiers, Human Review, and Marginal Task Value in Knowledge Work**

唯一主 RQ：

> **在具体知识工作任务中，更强 AI 计算的边际业务价值何时超过包括人工核验在内的完整边际成本？**

该问题不把识别策略写进 RQ，也不把“高价模型”当作理论构念。核心构念是 `value of computation`；模型档位和 token 预算是处理，`loss-adjusted net task value` 是本文归纳的操作化结果。

### 6.2 最低可行研究设计

第一阶段估计任务生产面。选择一家互联网企业中可重复、可评分且有真实后果的同类任务，在任务类别内随机分配：

1. human-only；
2. 低成本模型；
3. 高成本模型；
4. 低成本模型输出后，按预先登记条件升级至高成本模型。

每个 episode 记录模型、输入/输出/推理 token、重试、延迟、员工主动操作时间、复核与返工时间、盲评质量、任务是否达到业务阈值，以及错误的下游损失。相同员工应跨条件完成不同但等价的任务，并采用任务族与员工固定效应，以减少能力和任务难度混淆。

若目标还包括识别“多给多少 token”的因果效应，不能只观察模型自行消耗的 token；应在可技术控制的 AI 条件内进一步正交随机 reasoning effort、输出上限、采样次数或总调用预算。否则研究只能识别某个模型—工作流套餐的总效应，不能把结果解释成单个增量 token 的边际产出。[13,19]

第二阶段在留出任务上比较五类政策：全部 human-only、全部低成本模型、全部高成本模型、基于任务特征的静态 router、基于低成本模型输出与不确定性的条件升级政策。主要结果不是准确率，而是相对 human-only 的平均净值、预算约束下的总净值，以及相对 oracle 的 regret。[1,9–14]

第三阶段才研究组织实施：把学习得到的政策与员工自由选择比较。该比较可检验一个后续张力——员工拥有任务的局部信息，但企业承担 token 和错误成本；中央路由能够内部化成本，却可能遗漏员工掌握的上下文。此扩展需要单独引入授权、信息分散或委托—代理理论，不能在第一篇中无来源地并入。

如果研究问题改为“企业应给员工多宽的 token 额度”，主理论也应随之更换：Yu 的模型把 token 预算明确界定为在 productive experimentation 与 private gaming 之间配置激励的工具。[6] 这是企业—员工层的道德风险问题，不应与本文的任务内部 `value of computation` 选择混成一个模型。

### 6.3 不能遗漏的识别边界

- 不能只随机“价格提示”却把模型能力差异当成价格效应；不同模型档同时改变能力、延迟、上下文窗口和安全特征。
- 不能把内生 token 消耗回归到任务质量后称为 token 的因果回报；困难任务和失败重试会同时增加 token 与质量风险。
- 不能以员工自行选择 AI 的观测数据直接估计因果收益；困难任务更可能触发 AI，选择偏差方向不确定。
- 不能把节省的分钟自动记为企业利润；必须观察节省时间是否进入更多产出、更高质量或其他有价值任务。[18]
- 不能用同一个质量权重合并低风险文案与高损失任务；至少按业务损失函数分层。
- 模型和价格快速变化，因此应估计相对的 `task–model payoff surface`，并规定滚动重校准，而不是发布永久任务清单。[9–14,19]

## 7. 结论

**RQ1：** 最合适的主理论是 Bayesian decision theory 下的 `value of computation / metareasoning`；任务分配与人机互补解释异质性，`algorithm selection / LLM routing` 和运筹优化负责执行。[1–3,9–14]

**RQ2：** 技术研究已能在外生质量目标下选择模型和推理预算，组织实证已证明 AI 效果随任务和员工变化；两者共同缺少一个经企业任务数据识别、同时包含实际推理费、人工复核和错误损失的目标函数。[9–21]

**RQ3：** 2026 年工作论文已覆盖 `token leverage`、企业 AI tokenomics、token 预算激励、比较优势采用和管理者配置误判，因此“首次研究企业该不该花 token”不再成立。[4–8] 仍然清楚的增量是：**随机估计多模型档与条件升级在 `worker–task` 层级的边际净价值，并验证该配置政策是否优于统一模型和静态路由。**
